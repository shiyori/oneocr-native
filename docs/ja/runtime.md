# 既存の ONNX Runtime

[简体中文](../zh-CN/runtime.md) | [English](../en/runtime.md) | [日本語](../ja/runtime.md)

通常の導入では `runtime` 引数は不要です。ネイティブ SDK はアプリが既に読み込んだ互換ライブラリを優先し、その後に同梱・インストール済みリソースを検索します。利用可能なローカルのランタイムがない場合に、準備コマンドが固定の ORT 1.29.0 をダウンロードします。

ネイティブアダプターは C API 26 を要求し、CPU モデルセッションの作成によって必要な演算子を確認します。ORT 1.26 と 1.29 に対応し、その他の 1.x バージョンにも同じ API とモデル機能が必要です。SDK は `onnxruntime_go` に依存せず、ホストの Go バインディングのバージョンを引き上げません。

Engine は独自のセッションとランタイム・環境参照を所有します。終了時にはそれらを解放し、ホストのグローバル設定やランタイムを変更せず、他のモデルのセッションも破棄しません。すべての API オブジェクトは同じライブラリから作成します。ホストの別モデルの Session を共用することはありません。

異なる ORT ライブラリが複数読み込まれている場合、ホストは詳細設定で使用するものを明示的に選択する必要があります。読み込み済みライブラリが非互換の場合はエラーを返し、別のコピーの追加読み込みや更新は行いません。

Python は GPU 配布パッケージを含む、現在の環境の互換 `onnxruntime` モジュールを再利用し、OneOCR のセッションには CPU provider を指定します。コア wheel は CPU 配布パッケージを必須依存にしません。Android コア AAR もアプリのランタイムを再利用します。ARM64 CPU セッションには互換性設定 `mlas.disable_kleidiai=1` を追加します。

完全オフライン版には固定ランタイムと必要な再配布可能ファイルが含まれます。コア版も同じ準備コマンドを使用します。[インストール](installation.md)を参照してください。
