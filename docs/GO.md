# Go SDK

Module: `github.com/shiyori/oneocr-native`, Go ≥1.24, CGO enabled.

From the repository root or standalone source SDK:

```bash
go install ./cmd/oneocr
oneocr install --model /path/to/oneocr-cjk-en.ocrpack --runtime /path/to/libonnxruntime.dylib
oneocr recognize image.png
go run ./examples/basic /path/to/oneocr-cjk-en.ocrpack image.png
```

Use the platform's complete ONNX Runtime 1.29 CPU library. `ONEOCR_RUNTIME` or `Config.RuntimeLibrary` overrides automatic lookup next to the model/executable and SDK `lib/`. The desktop binary SDK includes ORT. `oneocr install` copies the package and runtime to the user configuration directory; use `--home` / `ONEOCR_HOME` for isolation. `OpenInstalled("")` uses this installation.

```go
import oneocr "github.com/shiyori/oneocr-native"

engine, err := oneocr.Open(oneocr.Config{ModelPath: model, RuntimeLibrary: runtime})
if err != nil { return err }
defer engine.Close()
result, err := engine.RecognizeFile(ctx, "image.png", oneocr.Options{})
```

`ModelPath` accepts `.ocrpack`. Legacy `BundleDir` remains supported; specify exactly one. Recognition is serialized per engine and supports context cancellation. Recognizers load lazily. Close is idempotent. Automatic script selection skips absent scripts with warnings; explicit unsupported scripts fail.

For an external local project:

```bash
go mod edit -replace github.com/shiyori/oneocr-native=/path/to/oneocr-native
go get github.com/shiyori/oneocr-native
```

No version tag has been published. Build this checkout locally; future releases use root tags such as `v0.1.0`. Models remain ordinary Git data in a nested data-only module and are not included in the root module ZIP. Source SDK archives likewise omit weights, Python and build caches.

Result fields include text, line quads, scripts, dimensions, elapsed time and warnings. Confidence and word boxes remain null. Complex inverse RTL, handwriting and natural vertical CJK have limitations. See the [project documentation](https://github.com/shiyori/oneocr-native).

## High-frequency calls and optional acceleration

Keep an Engine alive across frames. `Warmup(ctx)` primes all included models with small valid inputs; also recognize a representative image to warm the actual shapes. A single Engine serializes calls. For occasional concurrency, start with two independent Engines and one CPU thread each; the bounded [stream example](../examples/stream/main.go) demonstrates this pattern.

`Config.Backend` accepts `cpu` (default), `cuda`, or `directml`. Legacy `coreml` is retired: default `FallbackCPU` restores original-model CPU execution with an explicit diagnostic reason, while `FallbackError` rejects it. `DeviceID` selects a CUDA/DirectML adapter. `StageBackends` can keep individual stages on CPU. `FallbackCPU` permits a failed accelerated session to switch to its original CPU model; `FallbackError` reports the error. Neither setting forces every operator onto a GPU.

`CharacterClasses` selects `han`, `kana`, `hangul`, `latin`, and/or `digits` for CJK/Latin decoding. Empty selects all five; shared spaces and punctuation remain. This constrains characters, not language identity.

Use `AdaptationDir` only with an explicitly selected experimental model set generated by the Python `oneocr-native adapt` tool. Originals remain the default. `CacheDir` and `CoreMLComputeUnits` remain compatibility fields; CoreML is no longer initialized. `ProfilingDir` enables a short ORT execution trace; `Diagnostics()` after `Close()` then includes measured provider events. Registration alone is not evidence of acceleration. Keep profiling disabled during sustained production traffic.

```bash
oneocr recognize --model model.ocrpack --backend cpu --warmup image.png
oneocr recognize --model model.ocrpack --backend cuda --device 0 --fallback error \
  --adaptation-dir /path/to/candidate --cpu-stages detector \
  --profile-dir /path/to/profiles --diagnostics /path/to/new-report.json image.png
```

See [model adaptation, diagnostics and validation](ACCELERATION.md). CoreML adaptation and the v2 detector integer-grid recipes have been retired; loading these manifests returns an explicit error. The CoreML enum remains a compatibility alias whose default fallback uses original-model CPU. CUDA detector adaptation now preserves quantized operators. An isolated ORT 1.29 DirectML build now loads and runs the SDK on Windows; full stage accuracy and performance require separate acceptance. The default desktop runtime does not bundle CUDA/cuDNN or DirectML GPU dependencies.

Independent detection and cropped-line recognition: [API guide](STAGES.md). `Detect` returns regions only; `RecognizeLine` consumes an already cropped horizontal line. Encoded, file and RGB variants are available.
